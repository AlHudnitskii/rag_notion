# Метрики качества RAG-системы

В данном документе описаны все метрики, используемые для оценки качества ответов
RAG-системы (Retrieval-Augmented Generation). Метрики реализованы в модуле
`src/rag_quality_metrics.py` и `src/rag_statistics.py`.

---

## 1. ROUGE-1 Precision — Точность на уровне слов

**Обозначение в коде:** `relevance`

### Формула

```
        |W_ans ∩ W_src|
P = ─────────────────────
           |W_ans|
```

где:
- `W_ans` — множество значимых слов ответа (без стоп-слов),
- `W_src` — множество значимых слов всех извлечённых источников.

### Что отражает

Это компонента точности метрики ROUGE-1 (Recall-Oriented Understudy for Gisting
Evaluation). Показывает, **какая доля словарного запаса ответа встречается
в извлечённых источниках**. Высокое значение означает, что модель не придумывает
слова, которых нет в базе знаний — то есть ответ «заземлён» в источниках.

Формально P — это условная вероятность того, что случайно выбранное слово
из ответа окажется в источниках:

```
P ≈ P(слово ∈ W_src | слово ∈ W_ans)
```

**Диапазон значений:** [0, 1]. Значение 1 означает, что каждое слово ответа
присутствует в источниках.

## 2. ROUGE-1 Recall — Покрытие источников

**Обозначение в коде:** `source_coverage`

### Формула

```
        |W_ans ∩ W_src|
R = ─────────────────────
           |W_src|
```

### Что отражает

Вторая компонента ROUGE-1 — **Recall**. Измеряет, **какая доля словарного запаса
источников нашла отражение в ответе**. Высокое значение говорит о том, что
система не «упустила» существенную часть извлечённого контента.

В контексте RAG recall намеренно не максимизируется (источники могут содержать
много нерелевантного), поэтому он учитывается в общей оценке с меньшим весом,
чем precision.

**Диапазон значений:** [0, 1].

---

## 3. ROUGE-1 F1 — Гармоническое среднее точности и покрытия

**Обозначение в коде:** `rouge1_f1`

### Формула

```
         2 · P · R
F₁ = ──────────────
          P + R
```

### Что отражает

F₁-мера — **гармоническое среднее** между точностью (P) и покрытием (R).
Гармоническое среднее используется вместо арифметического потому, что оно
«штрафует» за экстремальный дисбаланс: если P → 0 или R → 0, то F₁ → 0,
даже когда вторая компонента близка к 1.

Это сбалансированная метрика лексического совпадения: ответ должен одновременно
опираться на источники (P) и использовать их содержательно (R).

Свойства:
- F₁ ≤ min(P, R) ≤ max(P, R)
- F₁ = 0, если P = 0 или R = 0
- F₁ достигает максимума 1, когда P = R = 1

**Диапазон значений:** [0, 1].

## 4. ROUGE-2 Precision — Верность на уровне биграмм

**Обозначение в коде:** `faithfulness`

### Формула

```
        |bigrams(ans) ∩ bigrams(src)|
Faith = ──────────────────────────────
               |bigrams(ans)|
```

где `bigrams(text)` — множество всех пар последовательных слов длиной > 2 символа.

### Что отражает

**Фразовая верность источникам** (faithfulness). Если ROUGE-1 Precision проверяет
отдельные слова, то ROUGE-2 Precision проверяет **словосочетания**. Это существенно
строже, так как совпадение пары слов значительно менее вероятно, чем совпадение
одного слова.

Метрика напрямую связана с «галлюцинациями» — когда модель порождает фразы,
которых нет в извлечённых данных. Низкое значение `faithfulness` — признак того,
что ответ содержит биграммы, отсутствующие в источниках, то есть модель дополняет
ответ из параметрической памяти, а не из базы знаний.

Именно поэтому `faithfulness` получает наибольший вес (w = 0.35) в итоговой оценке.

**Диапазон значений:** [0, 1].

## 5. Answer Completeness — Полнота ответа

**Обозначение в коде:** `completeness`

### Формула

```
C = 0.7 · min(|ans| / 500, 1) + 0.2 · I_struct + 0.1 · I_code
```

где:
- `|ans|` — длина ответа в символах,
- `I_struct ∈ {0, 1}` — индикатор наличия структурной разметки (списки, заголовки),
- `I_code ∈ {0, 1}` — индикатор наличия блоков кода.

### Что отражает

Эвристическая оценка **качества формы ответа**. Состоит из трёх аддитивных слагаемых:

1. **Длина** (вес 0.7): нормированная на 500 символов длина ответа. Порог 500 символов
   соответствует развёрнутому ответу (~80–100 слов). Ответы длиннее 500 символов
   получают максимальные 0.7 по этому слагаемому.

2. **Структура** (вес 0.2): бинарный признак — есть ли в ответе маркированные/нумерованные
   списки или заголовки markdown. Структурированный ответ легче воспринимать и
   содержит явно выделенные факты.

3. **Код** (вес 0.1): бинарный признак — есть ли блоки кода. Для технической базы знаний
   наличие кода в ответе свидетельствует о глубине обработки контента.

**Диапазон значений:** [0, 1].

## 6. Response Efficiency — Эффективность по времени

**Обозначение в коде:** `efficiency`

### Формула (кусочно-линейная)

```
          ⎧ 1.0,                                    t ≤ 5 с
E(t) =    ⎨ 1 − 0.03·(t − 5),                     5 < t ≤ 15 с
          ⎩ max(0.7 − (t − 15) / 60,  0.2),        t > 15 с
```

### Что отражает

Кусочно-линейная функция штрафует за увеличение времени отклика:

- **t ≤ 5 с** — мгновенный ответ, штрафа нет.
- **5 < t ≤ 15 с** — умеренное замедление, линейный спад от 1.0 до 0.7.
- **t > 15 с** — медленный ответ, спад продолжается с нижней границей 0.2
  (система всегда получает минимум 20% по этой компоненте, если она вообще ответила).

**Диапазон значений:** [0.2, 1.0].

## 7. Overall Score — Итоговая оценка

**Обозначение в коде:** `overall_score`

### Формула

```
S = Σᵢ wᵢ · mᵢ

  = 0.25 · rouge1_f1
  + 0.35 · faithfulness
  + 0.25 · completeness
  + 0.15 · efficiency
```

Проверка: Σ wᵢ = 0.25 + 0.35 + 0.25 + 0.15 = **1.00** ✓

### Что отражает

Взвешенная линейная свёртка всех компонент. Обоснование весов:

| Метрика       | Вес  | Обоснование                                                    |
|---------------|------|----------------------------------------------------------------|
| faithfulness  | 0.35 | Галлюцинации — критичнейший дефект RAG; наказываем строже всего |
| rouge1_f1     | 0.25 | Лексический баланс (P + R); отражает «попадание» в тему        |
| completeness  | 0.25 | Форма и развёрнутость ответа важна для пользователя           |
| efficiency    | 0.15 | Время отклика влияет на UX, но менее критично, чем содержание  |

### Интерпретация

| Диапазон   | Метка     |
|------------|-----------|
| S ≥ 0.80   | Excellent |
| 0.60 ≤ S < 0.80 | Good |
| 0.40 ≤ S < 0.60 | Average  |
| S < 0.40   | Poor      |

## 8. Shannon Entropy — Информационная энтропия ответа

**Обозначение в коде:** `entropy` (в `rag_statistics.py`)

### Формула

```
H = −Σᵢ pᵢ · log₂(pᵢ)
```

где `pᵢ = count(wᵢ) / N` — относительная частота слова `wᵢ`, `N` — общее число слов.

### Что отражает

Информационная энтропия Шеннона измеряет **разнообразие словарного распределения**
в тексте. Высокое H означает равномерное распределение частот — разнообразный
словарь. Низкое H означает, что несколько слов доминируют — шаблонный или
повторяющийся текст.

Для ответов RAG умеренно высокая энтропия (H ≈ 3–5 бит) свидетельствует
о насыщенности ответа. Очень высокое H (нет доминирующих понятий) или
очень низкое (текст-«рыба») — оба крайних случая нежелательны.

**Единица измерения:** биты (bits).

## 9. Type-Token Ratio (TTR) — Лексическое разнообразие

**Обозначение в коде:** `lexical_diversity`

### Формула

```
       |V|
TTR = ─────
        N
```

где:
- `|V|` — мощность словаря (число **уникальных** слов),
- `N` — общее число слов (с повторениями).

### Что отражает

TTR — простейшая мера **лексического богатства** текста. Значение 1.0
означает, что каждое слово встречается ровно один раз (максимальное разнообразие).
Значение → 0 означает постоянное повторение одних и тех же слов.

На практике TTR уменьшается с ростом длины текста (т. н. «закон Хердана»),
поэтому его следует сравнивать между ответами сопоставимой длины.

**Диапазон значений:** (0, 1].

## 10. Jaccard Similarity — Сходство по множествам

**Обозначение в коде:** `q_a_jaccard` (в `rag_statistics.py`)

### Формула

```
              |A ∩ B|
J(A, B) = ─────────────
              |A ∪ B|
```

где A и B — множества значимых слов двух текстов (без стоп-слов).

### Что отражает

Коэффициент Жаккара (Jaccard similarity coefficient) измеряет **степень
перекрытия двух множеств**. В контексте `q_a_jaccard` сравниваются множества
слов вопроса и ответа: высокое J(вопрос, ответ) означает, что ответ использует
терминологию вопроса, то есть **ответ «по теме»**.

Свойства:
- J = 0 при полном отсутствии общих слов,
- J = 1 при полном совпадении словарей,
- J симметрична: J(A, B) = J(B, A),
- J — метрика: удовлетворяет аксиомам метрического пространства через d = 1 − J.

**Диапазон значений:** [0, 1].

## 11. Cosine Similarity — Косинусное сходство векторов

**Обозначение в коде:** `cosine_similarity` (в `VectorStatistics`)

### Формула

```
              u · v          Σᵢ uᵢ vᵢ
cos(u, v) = ────────── = ──────────────────
             ‖u‖ · ‖v‖    √(Σᵢ uᵢ²) · √(Σᵢ vᵢ²)
```

### Что отражает

Косинусное сходство измеряет **угол между двумя векторами** в многомерном
пространстве эмбеддингов. В отличие от евклидова расстояния, оно инвариантно
к масштабу вектора (длине текста).

Применяется в двух контекстах:

1. **Сходство между чанками** (`cosine_distribution_stats`): анализирует, насколько
   семантически близки друг к другу извлечённые фрагменты. Высокое среднее
   косинусное сходство → чанки похожи → потенциально избыточная информация.
   Низкое → чанки разнообразны → хорошее покрытие темы.

2. **Сходство запроса с чанками** (`chunk_query_cosine`): среднее и максимальное
   значения говорят о том, насколько близко система «нашла» релевантные фрагменты.

**Диапазон значений:** [−1, 1]; для текстовых эмбеддингов обычно [0, 1].

## 12. Pearson Correlation — Корреляция Пирсона

**Обозначение в коде:** `correlations` (в `RetrievalAnswerCorrelation`)

### Формула

```
              Σᵢ (xᵢ − x̄)(yᵢ − ȳ)
r(X, Y) = ──────────────────────────────────────
           √[Σᵢ (xᵢ − x̄)²] · √[Σᵢ (yᵢ − ȳ)²]
```

где x̄ и ȳ — выборочные средние рядов X и Y.

### Что отражает

Коэффициент корреляции Пирсона измеряет **силу и направление линейной связи**
между двумя числовыми рядами. В системе вычисляются корреляции:

- **cosine_mean → quality**: связь между средним качеством поиска и качеством ответа.
  Если r > 0, то более похожие источники дают лучшие ответы.
- **diversity → quality**: связь между разнообразием чанков и качеством ответа.

Интерпретация |r|:

| |r|         | Сила связи  |
|-------------|-------------|
| 0.70 – 1.00 | Сильная     |
| 0.40 – 0.70 | Умеренная   |
| 0.20 – 0.40 | Слабая      |
| 0.00 – 0.20 | Пренебрежимая |

**Диапазон значений:** [−1, 1].

## 13. PCA — Метод главных компонент

**Обозначение в коде:** `pca` (в `VectorStatistics.pca_projection`)

### Формула (матричная форма)

```
Z = X · W_k

где W_k — матрица k первых собственных векторов матрицы ковариаций:
Cov(X) · wⱼ = λⱼ · wⱼ,   j = 1, ..., k

Доля объяснённой дисперсии:
          Σⱼ₌₁ᵏ λⱼ
EVR_k = ───────────
          Σⱼ₌₁ᵈ λⱼ
```

### Что отражает

PCA (Principal Component Analysis) проецирует d-мерные эмбеддинги на k-мерное
пространство (k = 2 для визуализации), сохраняя **максимальную долю дисперсии**.

`total_variance_explained` (EVR_k) показывает, какую долю информации из исходных
векторов удаётся сохранить в двумерной проекции. Значение EVR₂ > 0.5 означает,
что 2D-проекция несёт более половины информации, значение < 0.2 говорит о высокой
размерности данных, плохо редуцируемой до 2D.

## 14. Intra-Cluster Distance — Среднее внутрикластерное расстояние

**Обозначение в коде:** `intra_cluster_distance` (в `VectorStatistics`)

### Формула

```
         1        Σᵢ<ⱼ ‖ûᵢ − ûⱼ‖₂
ICD = ────────── · ─────────────────
       C(n, 2)            1

где ûᵢ = uᵢ / ‖uᵢ‖  — L2-нормированный вектор,
    C(n, 2) = n(n−1)/2  — число пар.
```

### Что отражает

Среднее евклидово расстояние между нормированными векторами чанков. Для
нормированных векторов:

```
‖û − v̂‖² = 2 · (1 − cos(u, v))
```

то есть ICD монотонно связано с косинусным сходством: высокое ICD ↔ низкое
среднее косинусное сходство ↔ **разнообразные чанки**.

Чем выше ICD, тем шире «семантический охват» индекса — система хранит
разнообразные фрагменты знаний. Низкое ICD говорит о дублировании или
узкой тематике базы знаний.
